# 真实文档夹具

`fixtures/perf/` 里的四份是**生成**的，尺寸精确、内容重复，用来量性能。这里要的是另一件事：
**真的有人这么写**的文档，用来量「能不能正确显示」——排版、公式、表格、标点、图片、以及各种
被粘坏的行。

## 一、收集要求

目标十份。按长度分三档（字数按**非空白字符**计，中文一字算一个）：

| 档 | 字数 | 份数 | 用途 |
| --- | --- | --- | --- |
| 短 | ≤ 1,000 | 4 | 日常随手记；打开、切换、渲染的最小单元 |
| 长 | ≥ 2,000 | 4 | 真的有人读的文档；折叠、大纲、滚动 |
| 极端 | 单行 ≥ 1,000 字符，或 ≥ 12 列宽表，或 ≥ 100 KB | 2 | 对抗用例；见 §9 的降级顺序 |

十份合起来必须覆盖下面每一条，缺哪条补哪条：

| 特征 | 至少 | 为什么 |
| --- | --- | --- |
| 公式（行内与块级都有） | 3 份 | 公式是最脆的一环：行内、块级、混排、长公式换行 |
| 表格（含一张 ≥ 8 列） | 3 份 | 列宽、对齐、横向滚动、窄窗口 |
| 超长行（一行 ≥ 1,000 字符且无换行） | 2 份 | 从 PDF 或网页粘过来就会这样 |
| 中文标点：顿号、书名号、破折号、省略号、引号 | 2 份 | 全角标点不能被替换、不能断行错位 |
| 图片（相对路径） | 2 份 | 缩放、缺图、导出内联 |
| 代码块（含一种长行代码） | 2 份 | 等宽、不折行、横向滚动 |
| 深嵌套（列表或引用 ≥ 4 层） | 1 份 | 缩进与左边距 |

## 二、来源与许可

- **只收自己写的，或明确允许再分发的。** 别人的文章、教材、论文、公司文档一律不收，
  哪怕只摘一段。仓库里不放有版权的内容。
- 每个人自己的笔记可以收，但要先删掉隐私：姓名、学号、邮箱、电话、地址、内部链接。
  收进来之前通读一遍，别指望事后找。
- 每份文件在下面的清单里记一行：来源（自写 / 本人笔记）、许可（与仓库一致）、
  是否已脱敏。

## 四、还缺两份（要真人的文档）

自造的文档有个共同的毛病：写的人知道它会被机器读，所以不自觉地写整齐了。缺的两份正好是
最容易写不整齐的两类，它们只能来自真实的笔记：

| 待收 | 要求 | 为什么必须是真的 |
| --- | --- | --- |
| 一份带公式的长作业／讲稿 | 长档，≥ 2,000 字，≥ 10 条公式（行内与块级混合），含中文标点 | 真实作业的公式长短悬殊、编号混乱、夹在列表里；这是 §7 导出验收的形态 |
| 一份从 Word／PDF 粘过来的长文 | 长档，≥ 2,000 字，至少一行 ≥ 1,000 字符，含表格 | 粘贴带进来的软换行、全角空格、`\r`、制表符，只有真粘过才有 |

收进来时按第二、三节的规矩：脱敏、记来源、写进上表。

## 五、怎么用

这一节的自造夹具不接产品，也不用它们跑测试；真实骨架按第六节的规矩进 CI。它们的用途是：

1. 手工打开，逐份核对显示（S2 起每加一种块级语法就过一遍）。
2. 导出 PDF 时当样本，看 §7 的审计行是否合理。
3. 谁的排版坏了，从一个最小的真实文档复现，而不是从生成夹具里复现。

生成夹具负责「大小」，这里负责「像」。

## 六、真实笔记的脱敏骨架

九份本人学习笔记的原文放在 `fixtures/real/local/`，该目录由仓库根的 `.gitignore` 排除，**不入库、不上报**。
可提交的是 `fixtures/real/skeletons/` 下的同名骨架：由 `tools/redact.py` 生成，保留标题层级、表格、公式、
代码块与符号，成段说明文字换成占位符。生成与校验：

```sh
python tools/redact.py fixtures/real/local fixtures/real/skeletons
python tools/redact.py --verify fixtures/real/skeletons
```

脱敏时表格单元格里的公式、实体、`\|` 与标题里的公式同样保留，只把成段中文换成占位符；
这个保真规则在 2026-11-26 补上，避免骨架把真正会炸的公式一起删掉。

来源：本人笔记；许可与仓库一致；已脱敏。渲染与导出的逐份核对报告只在本机保留，不入库。

**规矩：骨架入库、原文不入库；能过才进 CI，不过的进 `STATUS.md` 已知债。**
不用 xfail 把坏结果钉成基线：CI 的正样本白名单只有 `ci-positive.txt` 里的三份——
`指令系统`、`数的表示与运算｜完整复习笔记`、`中央处理器CPU`，它们的屏幕与导出均已核对通过。
其余六份先记在 `STATUS.md` 的「真实笔记夹具」里，不进 CI；每修好一条债，就把那一份骨架
加进 `ci-positive.txt`，CI 的真实夹具随之多一份。CI 只读白名单，并且生成骨架后要过
`tools/redact.py --verify`。
