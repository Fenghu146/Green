## 0.1 定案与增补（2026-11-26，S1 之后）

用户定案，不再问：

- **菜单栏保留**（文件/编辑/段落/格式/视图），顶栏不做两行；左侧栏「文件」页签保留。
- **`==文字==` 高亮**进语法：解析、编辑、渲染都支持；文件里原样保留，不改写；Typst 侧对应 `#highlight[...]`。它是非标准语法，写进 README「扩展语法」。
- **大纲节点是富文本**：标题里的 `$...$` 在树里渲染成公式（同一个 Typst 渲染器，字号更小），不显示源码；缓存键含字号；节点高度取文字行高与公式高度的 max；只给可见节点惰性栅格化，与正文共享同一个 LRU。
- **大纲要有树形折叠**：按层级缩进；有子节点显示 ▾/▸，叶子占位不显示但不跳动；面板折叠与正文折叠各存各的、互不联动，都按文件记忆（同一 view-state，不同键空间）；点三角只折面板子树，点标题跳到正文并展开路径上被折叠的祖先（正文与面板都展开）。
- **大纲只认 H1–H6**，不收录列表项；列表项是否进大纲进 `later.md`。
- Git 状态从状态栏移除（原条目指向已删除的 ElyTree，是死链）；真实 Git 状态若要做，另立任务。

S2 的公式尺寸与缓存（修正 §6.2）：

- 公式位图按 **设备缩放 × 2** 栅格化，不是固定 2×；缩放、字号、主题前景色变化都重新栅格化。
- 公式位图有 **LRU 上限**，正文与大纲共享，不能无限涨。

S2 的证据（缺一项即未完成）：5 万字 K2P p50/p95/p99、>16 ms 占比、滚动掉帧率；折叠/展开单次耗时且期间 shape 调用为 0（有计数手段）；`作业.md` 的 28 条公式（25 块级 + 3 行内，fixture 见 `crates/green-math/tests/fixtures/job-formulas.txt`）逐条对错 + 「中文 + 行内公式 + 中文」混排截图；5 万字单段结论；深浅主题下公式与折叠的截图；含公式标题的大纲截图；200 个含公式标题的文档打开大纲耗时与滚动掉帧。

## 0.3 组件库 fork 的代价（风险）

组件库以 `[patch]` 从 `vendor/ely-gpui-components` 换成仓库内副本，才能改 Markdown 树、公式与大纲。代价：

1. 上游从此和 Green 分叉，升级等于手工 rebase（`fc71e96` 之后的每个上游提交都要逐条挑）。
2. fork 出的部分保留原 MIT 声明并写进 `THIRD-PARTY-NOTICES`；`LICENSES/Ely-GPUI-Components-MIT.txt` 是原文。
3. 升 GPUI 版本时，这个 fork 是最先碎的地方——`vendor/gpui-pre` 与本 fork 的编译接口一起动，S6 前不做升级。
4. GPUI 本体也打了补丁：`vendor/gpui-pre` 里的 shape 计数（证明折叠不触发重排）是第二处 fork 点。计数用 feature gate（`shape-count`）编译期开关，release 默认关，不留全局原子递增的热路径；patch 内容记录在该 crate 的 `PATCHES.md`。升 GPUI 时这是**第三处**手工 rebase 的地方（组件库、GPUI 补丁、我们的组件库改动）。

## 1. 形态

```
┌──────────────────────────────────────────────────────────┐
│ green.exe（单进程，GPUI）                                 │
│  shell : 标签栏 · 工具条 · 大纲面板 · 状态栏 · 设置        │
│  core  : Block 模型 · 块渲染 · 编辑 · 折叠 · 原子保存      │
│  math  : 公式 → Typst（进程内）→ 图像，按哈希缓存          │
│  views : Registry（扩展名 → Provider）                    │
│  export: Block → .typ → Typst → PDF + 体积审计             │
│  fonts : fonts/ 随包，GPUI 与 Typst 共用同一批文件         │
└────────┬───────────────────────┬─────────────────────────┘
         │ 进程内                 │ stdin/stdout JSON
   plugins/markdown（内置）   外部插件进程（任意语言）
```

不变量：① 内容只存在磁盘文件里，无数据库、无自有格式、无 sidecar；② 所有落盘经 core（临时文件 + 原子替换）；③ `green-core` 不出现 `markdown` 字样；④ 插件崩溃/超时/清单坏都不影响启动；⑤ 无常驻服务、无安装器；⑥ **折叠/大纲只是视图状态，永不写入文件**；⑦ 编辑器与导出用同一批随包字体。

## 3. 插件：外部进程 + JSON（已定）

```
%APPDATA%\Green\plugins\<id>\  manifest.json + 任意脚本
{ "id": "csv", "version": "0.1.0", "apiVersion": 1, "extensions": [".csv"],
  "command": ["python", "csv_plugin.py"], "timeoutMs": 3000, "enabled": true }
```

stdin 收 `{apiVersion, path, ext, content(base64), contentOmitted}`，stdout 回 `{apiVersion, blocks[], meta}`。`content` 上限 8 MB；Block 九种。失败/超时/坏清单 → 降级 plaintext + 状态栏，不影响启动。
兼容：`apiVersion` 整数、超范围拒绝；`capabilities` 协商；两侧忽略未知字段；破坏性变更 `apiVersion += 1`，旧版留 2 个小版本；按 (path, mtime, size, 插件版本) 缓存。
加格式：**改 Green 0 个文件、不重编译、不发版**（这是保留插件系统的唯一理由）。以后再说：市场、沙箱、插件间依赖、native dylib。

## 4. 多标签

顶栏第二行是一排标签（沿用 ima 截图那两个并排的样子），标签左对齐，右侧留空给工具条。

每个标签是独立的文档会话，各自持有：

| 状态 | 说明 |
| --- | --- |
| 撤销栈 | 每个 tab 一条，互不串；跨 tab 的撤销是 bug |
| 光标与选区 | 各自独立，切回时恢复 |
| 滚动位置 | 各自独立（含水平偏移） |
| 折叠状态 | 各自独立（§5） |
| 脏标记 | 标题后一个点；保存后消失 |
| 视图模式 | 逐段渲染 / 源码 / 大文件只读，逐 tab |

规则：

1. **关闭脏 tab 拦一次**：保存 / 丢弃 / 取消，三选一；批量关闭（退出）逐个问，允许「全部保存」。
2. **单实例转发**：第二个文件 → **新建 tab 并激活**（不替换当前 tab）。若该文件已开，只激活原 tab。
3. **溢出**：tab 总宽超出时横向滚动（Shift+滚轮 / 触控板），右端出现下拉按钮列出全部标签；中键关闭；拖拽排序放 S3。
4. **会话恢复**：恢复 tab 顺序、活动 tab、每 tab 的光标/滚动/折叠；文件不存在 → 保留占位 tab 标「缺失」，不静默丢弃。
5. 关闭最后一个 tab → 新建空白文档（不退出应用）；退出应用走窗口关闭。

## 5. 折叠与大纲

### 5.1 正文按标题折叠

- 折叠范围：一个标题块 → 下一个**同级或更高级**标题之前。
- 判定基于 Block 树，所以 **代码围栏里的 `#` 天然不算标题**（不是靠正则）。
- 折叠只影响视图：隐藏范围内的块、标题行尾显示 `▸`；**绝不往 `.md` 写任何折叠标记**（不变量 ⑥）。
- 折叠/展开不重建文档模型，只改可见集合；隐藏块的排版结果留在缓存里，展开时直接复用。

### 5.2 大纲面板

- 左侧面板，**默认收起**（内容优先）；一键切换：工具条「目录」按钮 + `Ctrl+Shift+O`。
- 树跟着光标高亮最近标题；点击跳转并展开被折叠的祖先。
- **面板折叠与正文折叠相互独立**。理由：正文折叠是阅读状态（我暂时不想看这段），大纲折叠是导航状态（这棵树太长）；联动会让「在大纲里收起一章」意外把正文内容藏掉，属于破坏性副作用。VS Code / Obsidian 也是分开的。
- 大纲只读：不在面板里重命名、拖拽改层级（S3 以后再议）。

### 5.3 折叠状态是否记忆

**记忆，按文件**：键是「文件绝对路径 + 标题文本 + 同级序号」，不是行号（标题上下移动不失效；同名标题靠序号区分）。存放在 `%LOCALAPPDATA%\Green\view-state.json`，**不写进 `.md`，也不在文档旁生成 sidecar**。文件被删/改名 → 该条记录过期丢弃。

### 5.4 性能

折叠/展开改变的是可见集合与后续块的 y 偏移，不得触发任何**文字重排**（re-shape）。S2 验收：5 万字文档，单次折叠 ≤ 16 ms，且测量窗口内 shape 调用次数为 0。

## 6. 行内公式（S2 必须先解）

v0.3 把它列为风险并给了「降级为源码」的退路——**作废**。用户的笔记就是 `通项 $a_n=\left(\frac{2}{5}\right)^{n-1}$，是等比级数` 这种中文与行内公式混排，降级等于废掉主要用法。

### 6.1 事实：基座已经解了这个问题

`ely-documents/src/render/math_text.rs`（436 行）的做法：

1. 在段落文本里，用 **NBSP 胶水字符**把公式的宽度预留出来（`GLUE` 常量，永不换行 → 公式是原子）。
2. 段落仍交给 **GPUI 自己的文本排版** → 断行、避头尾、标点挤压、双向文本全部继承，不需要自建 line breaker。
3. 排版后，把公式图**盖在**预留的胶水区间上（`window.paint_image`）。
4. 公式比行高时，用 `TextStyleRefinement { line_height }` 抬高该行。
5. `swaps: (原始字节区间 → 绘制区间)` + `index_for_position` 让点击坐标映射回原文偏移。

所以 §6 的技术路径不是「拆成 run 序列再自己断行」，而是**沿用基座这套 glue-overlay，换掉渲染器**。

### 6.2 要做的事

- **渲染器换成 Typst**：进程内 `typst::compile` 一个单公式文档 → 取 `Frame` 的尺寸与 `baseline()` → `resvg` 栅格化成 `RenderImage`（按设备像素 2× 渲染）。这样编辑器与导出同引擎、同字体、同基线。
- **字体**：Typst 的 `FontBook` 指向随包 `fonts/`；GPUI 用 `TextSystem::add_fonts` 加载同一批文件（该 API 已确认存在）。
- **基线**：直接用 Typst `Frame::baseline()`，不用估 0.25em。
- **行高**：数学公式高于行高时按基座做法抬高该行（`line_height` refinement），不裁切。
- **跨行**：公式原子不可断；若比整行还宽 → 独占一行、允许横向滚动，不拆、不缩到看不清。
- **光标**：公式是**不可分割的原子**。光标只能停在它前后；`Backspace`/`Delete` 整条删除（一步撤销）；点击公式 → 打开一个小浮层编辑 `$...$` 源码，回车重排、Esc 取消；编辑期间正文不重排其他块。

### 6.3 代价（估）

| 工作 | 估 |
| --- | --- |
| 换渲染器（Typst 进程内 + 取基线 + 2× 栅格化） | 2–3 天 |
| 行高/基线/清晰度调平 | 1 天 |
| 公式原子的光标行为 + 源码浮层 + 撤销合并 | 1–2 天 |
| 断行/避头尾/标点挤压 | **0**（继承 GPUI，不自己做） |

### 6.4 如果不可行

若 Typst 进程内（`Frame::baseline()` 或 SVG 输出）在集成时不可用，**如实记录并按此顺序退**：

1. 显示继续用基座的 RaTeX，导出用 Typst → 明确写「两副面孔」，并在设置里给出「公式外观以导出为准」的说明；
2. 公式区域改为自绘 canvas（自己管行内排版）→ 成本翻倍，需重新评估 S2；
3. **不接受**「降级为 `$...$` 源码」——那等于砍掉用户的主要用法。

## 7. 导出（Typst，已定）

22 MB 的成因已复现（v0.3 §5.1 数据保留）：ElyMark 的 HTML 里 **0 张图片、28 个内联 SVG**；交给 MuPDF 1.28.6 转 PDF 后 **2 页 4,605,496 字节**，其中字体 4,140,464（89.9%，全部 `sub=no`）、图片 387,219（8.4%，28 张 = 28 公式，96 dpi 未压缩）。同一组 26 个公式用 Typst：1 页 56,525 字节，字体全部 `sub=yes`，0 张图片。

现在字体随包，导出链不再依赖系统字体：Typst 的 `FontBook` 只装 `fonts/` 里那几份 OFL 字体，子集化由 Typst 默认完成。

审计（`lopdf`）：页数、总字节、逐字体字节（`FontFile2/3`、`/Length1`）、图片（`/Filter`、按哈希去重）、内容流压缩、每页最大图片覆盖率。导出后固定一行：

```
export pdf: pages=12 bytes=845120 fonts=[{"name":"SourceHanSansSC","bytes":412000}] images=0/0 (dup:0) compressed=true max_image_coverage=0.0%
```

阈值：单页均值 > 500 KB、单字体 > 3 MB、图片占比 > 70%、任一图片覆盖页面积 > 40% → 日志 + 状态栏。
验收：用户 `作业.md` **≤ 2 MB**、导出 ≤ 10 s、`compressed=true`、`max_image_coverage ≈ 0`、`pdffonts` 全 `sub=yes`。

## 10. 阶段与完成定义

- **S1 基座与外壳**：剪枝、构建、能开 .md（已达成）；多标签骨架（§4）；工具条按 §8；正文居中；浅深主题；随包字体接入（GPUI `add_fonts` + Typst `FontBook` 同一批文件）。**退出**：增量 ≤ 60 s；两 tab 并排截图；中文字体在两个 tab 都正确；增量体积落在 80–100 MB。
- **S2 Markdown、折叠与公式**：逐段渲染、编辑闭环；折叠 + 大纲（§5）；行内 + 块级公式（§6）。**退出**：5 万字 K2P p95 ≤ 16 ms、掉帧 < 1%；折叠 ≤ 16 ms 且 shape 为 0；用户 `作业.md` 的 26 个公式全对、中文混排行内公式正确；单段用例有书面结论。
- **S3 文件与安全**：外部改动、单实例转发（新建 tab）、原子保存 + 占用重试、自动保存/崩溃恢复、撤销、关闭脏 tab 拦截、会话恢复。**退出**：杀进程不丢稿；外部改文件不静默覆盖；占用保存有明确错误；退出重开 tab 顺序/光标/折叠复原。
- **S4 插件**：supervisor、契约、清单、启停。**退出**：Python CSV 插件工作；超时降级；坏清单不影响启动；加格式零改动。
- **S5 导出**：Block→`.typ`、Typst 调用、`pdf_audit`、阈值。**退出**：`作业.md` ≤ 2 MB；审计齐全；`pdffonts` 全 `sub=yes`。
- **S6 打包与硬化**：zip 免安装、便携数据目录、VCRT 验证、日志、许可页（含 OFL 全文）、10 份真实文档。**退出**：干净 Win11 解压可用；许可文件齐全。
